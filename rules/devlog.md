# DEVLOG 开发日志协议

> 面向任何 AI coding agent 的开发日志约定。目标：跨会话 / 跨模型 / 跨运行时的工作记录，永远可追溯「谁、在什么环境、基于什么基线」写下的这条日志。版本 v1.0。
>
> **协议家族**：**devlog 记过程** · [journal / handoff](journal-handoff.md) 记日常与交接 · [registry](registry.md) 记环境资产 · [skills](skills.md) 管能力资产 · [iron-rules](iron-rules.md) 管行为约束 · [search-chain](search-chain.md) 管联网获取。

## 1. 文件与条目结构

- 每个项目一个 `DEVLOG.md`（置于项目根或 `docs/`）。
- **倒序追加**：最新条目在最上，旧条目永不改写。
- 一天一节（或一任务一节），标题带日期与主题，并给条目编号（`#1`、`#2`…，供接力引用）。
- 每节固定四块：**做了什么 / 决策 / 踩坑 / 产物**。

## 2. 执行元信息块（必须）

每条新条目必须以「执行元信息」块开头，七要素：

| 要素 | 说明 |
|---|---|
| **平台** | agent 运行的平台 / 界面（CLI、IDE 插件、自治 harness…） |
| **会话** | 会话标识 |
| **模型** | 实际使用的模型与思考档 / 推理档（如 `thinking: high`） |
| **模式** | 本次工作模式一句话（功能攻坚 / 排查 / 收尾…） |
| **花费** | 订阅内 / 免费 / 计费额度 |
| **接力点** | 接哪条前条目或交接文档继续（首发条目写「新项目启动」） |

- 缺元信息的条目视为不合规：补全后才能收工。
- 模板见 [`templates/DEVLOG-entry.md`](../templates/DEVLOG-entry.md)，成品示例见 [`examples/devlog-example.md`](../examples/devlog-example.md)。

## 3. 接力对账（Relay Reconciliation）

- 跨模型 / 跨运行时接力的条目，必须注明 **基于 #<前条目标识>**。
- 写之前先对账：确认前条目之后，基线（代码 / 文档 / 状态）有没有被其他会话推进。
- 发现基线已推进 → **先核对差异再写，绝不直接覆盖**。这是日志层面的乐观锁：提交前发现版本已变，先合并再落笔。

## 4. 反模式

- **无元信息的流水账**：三个月后没人知道这条日志是什么环境写的。
- **覆盖式更新**：重写旧条目而不是倒序追加。
- **只记成功不记踩坑**：踩坑（现象 → 根因 → 解法）是日志里最值钱的部分。
