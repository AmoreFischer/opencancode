# Hypothesis Ledger（假设台账 · 预算制换线）

> **一句话**：长任务排障最大的隐性成本不是失败，是**隧道视野**——在同一假设上无限下钻。给每个假设发时间片预算、用计数触发强制换线、用五态台账让假设状态跨会话存活。
> 与 [journal-handoff.md](journal-handoff.md)（台账行随交接延续）、[systematic-debugging](../skills/systematic-debugging/SKILL.md)（四阶段调试，本协议管其中「根因假设」的预算）配套。

## 为什么需要

LLM agent 排障的三种经典烧法：

1. **同手段复读**：同一命令改改参数连跑五次，每次拿到同样的错误——信息量为零，上下文烧了五轮；
2. **同假设下钻**：换了好几种手段，但其实都在验证同一个假设，四次的「新尝试」没有产生新类别的观测；
3. **换会话失忆**：上个会话已经排除了什么假设、什么条件下可以复活，新会话一无所知，从头再排除一遍。

本协议用「预算 + 计数 + 分级 + 台账」四件套治理这三件事。

## 核心概念

- **假设（H）**：对故障根因/问题答案的一个可判断陈述（「是缓存没刷新」「是版本不兼容」）
- **手段**：验证某假设的一种具体方法（跑某命令、读某日志、打某断点）
- **时间片**：一次完整的「假设 → 判别实验 → 结论」闭环（**不是**单次工具调用——一个片内可以有多步）
- **判别实验**：其结果能把假设推向「支持」或「否证」一边的实验；两边都可能的实验才有片的价值

## 时间片预算

- 每个假设默认 **2 片**；第 3 片起须凭**延期**继续——一行写明：下一实验是什么、判别什么、为何仍值得。
  - 写不出判别点 = 不获延期；
  - 下一实验必须产生与上一实验**不同类别**的观测（改参数/换命令不产生新类别）。
- 最多延 **2 次**，之后换假设或上报。

## 计数触发（硬换线，不靠自觉）

| 触发 | 条件 | 动作 |
|---|---|---|
| 手段级 | 同一手段**连续 2 次**得到同一观测或同一错误 | 第 3 次禁止同路径，必换验证手段 |
| 假设级 | 同一假设下**同类观测/错误累计 4 次**（按信息类别归并，跨手段不清零） | 换假设（计数只随换假设清零） |

## 换线分级（越往下越贵，门槛越高）

| 换什么 | 门槛 |
|---|---|
| 换**手段**（同假设换个验法） | 自由 |
| 换**假设** | 须给一条**否证证据**（旧假设为什么站不住了） |
| 降**目标** / 缩**范围** | 须用户确认——agent 不得自行降级，「做不出来就少做点」不是 agent 的决定 |

## 台账五态

每个假设/未知项标一个状态，随工作延续：

```
open → investigating → resolved
                    ├→ contradicted（被证伪）
                    └→ blocked（阻塞待条件）
```

- **contradicted 与 resolved 分开记**：证伪的假设连同证据留档——防「无据复活」（三个月后有人把早已证伪的假设当新思路重新提出）；
- **resolved 须过一次复核才销账**：判别式重跑一遍，或换一个独立来源确认；
- 台账行随交接文档（handoff）跨会话延续，**计数不清零**；已闭合项移入当日工作日志留档，交接里只留未闭合项。

### 台账行格式

```
H{n}「{假设一句话}」｜已排除：{最强的否证一条}｜复活条件：{可观测判别式}｜片 {已用}｜同类观测累计 {n}/4｜已延 {n}/2
```

**复活条件必须是可机判的**（命令输出 / 日志行 / 版本号 / 事件），「等以后再说」这类空话视为未记账。

## 人在场两档

| 档 | 适用 | 行为 |
|---|---|---|
| `interactive` | 有人盯的主会话（默认） | 不确定就问；「继续」不构成拒绝理由 |
| `autonomous` | 子代理 / 后台 / 定时任务（未声明默认此档） | 不等待、不空转：记账换线、**只换步不降目标**，复活条件留档待审，按汇报完整性分级上报 |

## 失败处置两条（预算的边界）

1. **重试/次数/停止限制不因换任务、换会话或换表述而重置**——「换个说法再试五次」不产生新预算；
2. **工具失败不作废任务与已获授权**——先核对真实状态与已完成步骤；结果不明时不重复写入，只续接未完成部分。

## 附：ADR 三重门控

排障/设计过程中做出**架构决策**时，同时满足三个条件才值得记一条 ADR（架构决策记录）：

1. **Hard to reverse** — 改主意的代价很大；
2. **Surprising without context** — 未来读者会疑惑「为什么这样做」；
3. **Result of a real trade-off** — 确实有过多种替代方案。

三条不全满足的，普通日志一行带过即可——ADR 是给「不解释就会被人好心改掉」的决策用的。
