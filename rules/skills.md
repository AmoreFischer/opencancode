# 技能管理协议（Skill Registry）

> 面向任何 AI coding agent 的能力资产管理约定：技能怎么登记、索引怎么生成、跨平台怎么保持一致。目标：消灭手抄触发词表——任何平台、任何会话都能对账出「有哪些技能、版本对不对」。版本 v1.0。
>
> 与 [registry 协议](registry.md) 分工：registry 登记**环境资产**（模型 / 代理 / 端口），本协议管理**能力资产**（技能）。

## 1. 单一源（必须）

- 每个技能一个目录 `<skills-dir>/<id>/SKILL.md`，其 frontmatter 是唯一权威：

```yaml
---
name: <技能 id>
description: <一句话用途，供索引与触发判断>
version: <x.y>
triggers: [<触发词>, ...]
source: original
---
```

- 任何触发词表、索引、清单都是 frontmatter 的**派生物**；不允许脱离 frontmatter 手写技能条目。

## 2. 变更即重建（必须）

- 新增 / 修改 / 退役技能后，必须重建两个派生物：
  1. 机器清单 `SKILLS.json`（id + version + description）；
  2. 各平台入口的触发词表（`AGENTS.md` / `CLAUDE.md` / skill-index 等引用处）。
- 重建 = 读全部 frontmatter → 重新生成。**手抄一处，就是漂移的开始。**

## 3. 版本快照（必须）

- 改技能内容必须递增 `version`，`SKILLS.json` 随之更新。
- 进位约定：改行为或触发词 → 小数位 +1（`1.1`→`1.2`）；破坏性改动 → 整数位 +1（`1.x`→`2.0`）；纯措辞微调可并入下次行为变更。

## 4. 启动对账（必须）

- 会话启动时（或用户要求时），对比 `SKILLS.json` 与本平台已加载 / 本地目录的技能集；
- 缺技能、版本不一致 → **提示用户刷新 / 更新，不静默带着旧清单干活**。

## 5. 同步链路（必须）

- 技能变更须走完「落盘 → 提交 → push → 其他平台 pull」才对其他平台生效；
- **未提交 = 全平台不可见**——「我改过了」不等于「已同步」；
- 平台入口文件（触发词表所在文件）与技能**同仓同 commit**，避免清单与内容版本错位。

## 反模式

- **触发词表手抄多处**：各处不一致只是时间问题——一切索引从 frontmatter 重建。
- **改了 SKILL.md 不递增版本、不重建清单**：对账失去锚点。
- **带着旧技能清单继续干活**：不对账、不提示，用户以为 agent 会，实际不会。
