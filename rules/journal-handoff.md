# Journal 与会话交接协议

> 面向任何 AI coding agent 的日常工作记录与交接约定。与 [devlog 协议](devlog.md)配合使用：DEVLOG 记「项目账」，journal 记「日常账」，handoff 记「交给下一个会话的账」。版本 v1.1（v1.1 增五问结构：待用户决策/继续条件两节 + 证据分级标注 + 开工侧恢复顺序，吸收 loopx 五问模型与恢复仪式）。

## 1. 每日 Journal

- 工作区级目录：`journal/YYYY-MM-DD.md`，一天一文件。
- 每次操作 / 会话追加一条：时间 + 一两句话（做了什么、结论）。
- 多个 agent 共用同一 journal 时，每条记录加 `[<agent-名>]` 前缀，避免混淆。
- 任何密钥 / token 写入 journal 前必须脱敏。

## 2. 会话交接（Handoff）

会话结束前更新 `journal/_handoff.md`，让下一个会话（哪怕换了模型 / 平台）能无缝续接。

**结构**（全文 **< 100 行**，电报体、删客套；五问覆盖：目标+授权 / 待办 / 待人决策 / 证据 / 继续条件）：

```markdown
# Handoff — <YYYY-MM-DD HH:mm>

## 会话目标
<一句话，含当前授权范围>

## 已完成
- [x] <具体产出 + 关键决策>（附证据：路径 / 验证输出 / 证据级别——「文件已改 / 模拟通过 / 真实调用成功 / 线上生效」不混称）

## 未完成
- [ ] <任务 + 阻塞原因>

## 待用户决策
- [ ] <需用户拍板的事项 + 候选选项>

## 上下文快照
- 变更文件：<清单>
- 分支 / 环境状态：<clean 或 dirty + 关键状态变量>
- 基线条目：基于 #<DEVLOG 前条目标识>

## 继续条件
- 预算水位：<API 配额 / 订阅窗口余量；有监控链路则开工先查，达停止线报告等指示>
- 恢复入口：<下个会话从哪续（文件/命令/入口）>

## 下次第一步
<具体起始指令>
```

**约束**：

- `< 100 行`；安全相关的状态必须完整记录，不受篇幅约束。
- 最后一个写入者直接覆盖 `_handoff.md`——每个 agent 写自己的最新状态，属设计内行为（更早状态由当日 journal 与 DEVLOG 兜底）。
- 「待用户决策」项不得由下一个会话自行代答（「继续」只延续已批准范围，不扩权）。

## 3. 交接消费（开工侧）

新会话按 handoff 续接时的恢复顺序：

1. 读「会话目标」，确认授权范围未变。
2. 核对「已完成」项证据——证据级别不足的按未完成处理，不虚称完成。
3. 查「继续条件」的预算水位（有监控链路才查；达停止线 → 报告用户等指示，不硬跑）。
4. 按「下次第一步」启动。
