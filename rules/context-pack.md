# 上下文包（Context Pack）派活协议

> 把任务交给另一个执行方（子代理 / workflow agent / 其他窗口 / 低档模型）时，prompt 按本协议构造：注入什么、注入多少、如何回传。核心原则：给执行方的不是「开放问题」，而是**已消解歧义的任务卡**——把「这个任务已经足够简单」的判断前置到设计阶段，这正是模型级联（cascade）省钱的本质。版本 v1.0。
>
> [溯源: FrugalGPT（arXiv:2305.05176，级联可匹配最强单模型性能并省最多 98% 成本）；Anthropic《Effective context engineering for AI agents》（子代理回传 1-2k token 蒸馏摘要 / 指令的 right altitude）；Aider repo map（tree-sitter AST + 图排序，~1k token 装下全仓骨架）]

## 1. 两档制与准入门槛

| 档位 | 字段 | 适用 |
|---|---|---|
| **full pack** | 七段全填 | 编程任务、跨窗口/跨运行时派活、workflow 编排 |
| **minimal pack** | goal + boundary + acceptance 三段 | 需求已清楚、只是活小 |

**准入门槛（防「披模板外衣的许愿式派活」）**：minimal 省的是「写包」的功夫，不能省「想清楚」的功夫——需求本身模糊时，无论任务多小，先做需求澄清，再进本协议。自检判据：goal 写不出「不做什么」、acceptance 写不出可执行的验证命令 = 需求未澄清。

## 2. 七段结构

| 段 | 必填 | 内容 | 防的失败模式 |
|---|---|---|---|
| `meta` | full | 派发方 / 执行方模型档位 / token 预算 / 任务拓扑（见 §4） | 低档模型接到超纲任务、拓扑错配（顺序任务被拆成多代理） |
| `goal` | 全档 | 一句话：做什么 + 为什么 + **不做什么** | 许愿式派活——只给 what 不给 why，执行方自行脑补范围 |
| `boundary` | 全档 | 改动白名单（精确到文件）/ 只读参考清单 | 顺手重构、精确修改失守 |
| `context_injection` | full | 三层注入，见 §3 | 全量注入——成本线性涨且上下文越长检索精度越低 |
| `acceptance` | 全档 | 可验证完成信号：测试命令 / 预期输出 / 行号级 diff | 「原则性符合不算完成」，证据分级（文件已改 ≠ 测试通过 ≠ 真实调用成功） |
| `forbidden` | full | 负面清单：禁扩范围 / 禁对模糊处静默假设（标记回问而非猜）/ 禁跳过验证 | 执行方「合理假设」后跳过模糊处 |
| `return_contract` | full | 回传 ≤1.5k token 蒸馏摘要 + 证据；阻塞时回传问题而非猜测 | 子代理回传数万 token 探索过程污染主会话 |

指令密度遵循 **right altitude**：具体到能引导行为，抽象到保留启发式——既不是硬编码 if-else 的脆规则，也不是默认共享上下文的空泛口号。

## 3. 分层注入（L0/L1/L2）

| 层 | 形态 | 规则 |
|---|---|---|
| **L0 符号签名** | repo-map / 代码图谱工具产出的符号、调用链、引用骨架 | **编程任务必填**；没有此类工具时用 glob+grep 手工构造符号清单 |
| **L1 路径引用** | 文件路径 + 行号 / 关键段落引用 | 默认层；执行方按需展开 |
| **L2 完整文件** | 整文件内容 | 仅必要时装载；**能被 L0/L1 替代时禁止** |

## 4. 任务拓扑三型（拆不拆多代理的判据）

拆分任务前先分类拓扑——拆不拆不是信仰题，是任务分类题：

| 拓扑 | 判定特征 | 执行形态 | 实证依据 |
|---|---|---|---|
| `sequential` | 后步依赖前步产出、状态强耦合 | 单会话 + 上下文压缩/交接续跑，**禁拆多代理** | 顺序推理任务所有多代理变体降 39-70% |
| `parallel-explore` | 子任务独立、产出可蒸馏（调研/审查/多文件独立改） | 子代理并行 + **集中式汇总** + 各回传蒸馏摘要 | 可并行任务集中式协调 +80.9%；误差放大：集中式 4.4× vs 无协调独立 17.2× |
| `stable-direct` | 该类任务模型历史上能稳定做对 | 不加编排层直接做，可降档到便宜模型 | 单代理基线超过 ~45% 后，协调的边际收益转负（β=-0.408） |

配套止损判据：同一子任务失败 2 次后，第 3 次禁止同路径重试，必须换验证手段（日志插桩 / 最小复现 / 对照实验）——依据「更多 LLM 调用」的非单调性（难查询越调越糟，arXiv:2403.02419）。

[溯源: arXiv:2512.08296《Towards a Science of Scaling Agent Systems》180 配置 × 3 模型族控制实验]

## 5. 回传契约

- 蒸馏摘要 ≤1.5k token：做了什么 / 关键决策 / 改动文件清单 / 验收结果；
- 证据随行：行号引用、测试输出原文（截断到关键行）；
- 阻塞回传格式：`[BLOCKED] <具体阻塞点> + 已尝试路径`，禁止以猜测冒充完成。

## 反模式

- **披模板外衣的许愿式派活**：模板填了但 goal 还是「让页面变好看」——需求未澄清，先澄清再入协议；
- **全量注入代替 L0 骨架**：整仓代码塞给执行方——成本线性涨、检索精度还在跌；
- **子代理回传探索流水账**：主会话上下文被几万 token 过程记录污染——只要蒸馏结论+证据；
- **顺序任务上多代理编排**：状态强耦合的链式工作拆给并行代理，返工大于产出；
- **模型已稳定做对的任务加编排层**：协调开销纯赔——直接做或降档执行。
