# AI Coding Agent 工程铁律（Iron Rules）

> 面向任何 AI coding agent 的行为约束合集：把反复踩坑换来的工程纪律，编码为 agent 必须遵守的硬规则。优先级：本文件 > agent 自有默认行为。版本 v1.0。
>
> 标注「来源」的条目为吸收改写（汇总见 [SOURCES.md](../SOURCES.md)）；未标注的为原创沉淀。

## 一、流程与原则

1. **规则前置** — 开始任何非平凡任务前，先读项目的规则文件（`AGENTS.md` / `rules/` 等）与适用流程约定；不在未知规则的状态下动手。
2. **流程门禁** — 非平凡任务走「设计 → 确认 → 实现 → 验证 → 收尾复盘」完整链，不跳步、门禁未过不进下一步；小任务可简化，但不可跳过验证。
3. **完整生命周期 + 验证门禁** — 每个资源（连接、文件句柄、进程、挂起状态）必须有创建 → 使用 → 释放路径（`with` / `try-finally`）；挂起等待必须有超时与默认动作；任务完成前必须有最终验证（测试通过 / 结果确认 / 用户确认）——**原则性符合不算完成，必须实际检验通过**。
4. **单一职责** — 模块 / 函数只做一件事；函数过长考虑拆分；拆后各部件可独立测试。
5. **防御式编程** — 不信任外部输入（API 响应、用户消息、文件内容）：类型校验 + 范围校验 + 边界处理。
6. **DRY** — 每个知识片段有唯一权威表述；出现第二次就抽函数 / 常量。
7. **KISS** — 朴素简单，禁止炫技与过度工程；3 行能解决不写 30 行。
8. **失败可观测性** — 异常必须带上下文日志；静默吞异常 = 严重错误。
9. **向后兼容** — 破坏性变更升主版本号，语义化版本。
10. **避免过早优化** — 先清晰正确，再谈性能；没有 profiler 数据不优化。
11. **代码即文档** — 注释只写「为什么」，不写「做什么」。
12. **先想清楚再动手** — 不确定就问；多种理解列出来；有更简单的方案就说出来。
    > 来源：Karpathy "Think Before Coding"，经 [multica-ai/andrej-karpathy-skills](https://github.com/multica-ai/andrej-karpathy-skills)
13. **简单优先** — 50 行能解决不写 200 行；不添加没被要求的功能与抽象。
    > 来源：Karpathy "Simplicity First"（同上）
14. **精确修改** — 每一行修改可追溯到具体需求；不顺手重构没坏的东西。
    > 来源：Karpathy "Surgical Changes"（同上）
15. **目标驱动** — 每个任务先定义成功标准，循环直到验证通过；执行中不私自扩范围。
    > 来源：Karpathy "Goal-Driven Execution"（同上）
16. **依赖纪律** — 新增依赖前评估必要性 / 维护状态 / 替代方案；能用标准库就不用第三方；生产依赖锁版本；警惕新发布、低下载量的包（slopsquatting），安装脚本不可信时用 `--ignore-scripts` 类开关。
17. **关键逻辑测试覆盖** — 数据处理 / 状态机 / 核心算法必须有测试覆盖；多模块交互的改动至少有集成测试。
    > 来源：[github/spec-kit](https://github.com/github/spec-kit)（Test-First），适配 agent 工作模式
18. **禁止静默假设 · 暴露权衡** — 不确定必须显式标记并追问（如 `[NEEDS CLARIFICATION: …]`），不允许「合理假设」后直接跳过；跳过任何问题必须说明原因并告知用户；多个可行方案并列时，列出各自 tradeoffs 请用户决策，不替用户选。
    > 来源：Karpathy "Don't Assume / Surface Tradeoffs" + spec-kit 标记法

## 二、环境隔离

19. **环境隔离** — 项目依赖进虚拟环境 / 容器，禁止污染系统环境；执行前确认用的是隔离环境的解释器与包管理器。
    > 来源：Python 官方 venv 指南 + claude-code best practices，泛化为跨语言要求

## 三、Git 与凭据安全

20. **Git 红线** — 永不 force push；已推送的 commit 不重写历史（公共 / 共享分支不 rebase）；合并前展示 diff 预览并等待确认；不丢弃未提交变更（先 stash）。
21. **凭据不进库** — 密钥 / Token / 密码走 `.env` 或环境变量 + `.gitignore`；写日志、文档、commit message、配置示例前自动脱敏——**示例里的 key 哪怕自己用，也必须换成占位符**。
22. **提交前密钥扫描** — `git add` 前对改动跑密钥正则（`sk-`、`AKIA`、`Bearer …`、`api_key=` 等模式），命中真实值必须脱敏或排除；已提交的泄露 → 立即在平台 rotate（删文件无用，历史仍在）。

## 四、服务与运维

23. **服务只绑本机** — 面向本机 / 内网的服务一律绑 `127.0.0.1`，不绑 `0.0.0.0`；对外暴露走隧道 / 网关并显式声明。
24. **危险操作禁令** — 禁不可逆递归删除（`sudo rm -rf` 类）；删非空目录前必须二次确认或先备份。
25. **并发与定时纪律** — 同一外部 API 的调用串行或限速，禁止无序并发触发配额；收到 429 按 `retry-after` 退避重试（至多 2 次）；定时任务不错设在整点（偏移 15-25 分钟），设定前核对现有任务时间线避免资源竞态。

## 五、排查方法论

26. **先搜后造（Search Before Build）** — 实现新功能 / 排查疑难前，先搜上游（issue / PR / 官方文档 / 权威站）借鉴现有方案，不闭门造车；采纳外部方案标注来源。
27. **链路要活（Don't Tunnel）** — 单点深钻 2-3 轮无进展即换路径：换工具 / 换渠道 / 换验证手段；组合「日志取证 + 最小复现 + 对照实验」推进。
28. **对话历史即证据** — 排查 agent 自身的行为问题时，优先从对话与日志历史取证，不靠记忆与猜测。

## 采用方式

把本文件放进仓库（如 `docs/iron-rules.md`），并在 `AGENTS.md` / 系统提示里声明「铁律见 `<路径>`，优先级高于 agent 默认行为」；或先粘 [snippets/AGENTS-rules.md](../snippets/AGENTS-rules.md)（Top 10 精选）起步。
