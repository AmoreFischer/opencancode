# 注册表协议（Registry）

> 面向任何 AI coding agent 的环境资产登记约定。目标：把「有哪些模型、各 agent 怎么调用、走哪个代理端口、依赖哪些外部 API、本地跑着什么服务、常用工具在哪」这类一次性配置，写进固定位置的清单，跨会话 / 跨 agent 复用——写一次，处处可查，不再每段对话重复强调。版本 v1.2。
>
> **协议家族**：[devlog](devlog.md) 记过程 · [journal / handoff](journal-handoff.md) 记日常与交接 · **registry 记环境资产** · [skills](skills.md) 管能力资产 · [iron-rules](iron-rules.md) 管行为约束。
>
> 与本仓其他协议并列：[devlog](devlog.md) 记过程，[journal / handoff](journal-handoff.md) 记日常与交接，**registry 记环境资产**。

## 1. 登记什么

按资产类型一表，置于工作区 `registry/` 目录（从 [templates/](../templates/) 复制起步）：

- `models.md` — 模型清单：每个模型是什么、在各 agent 里怎么调用
- `proxy.md` — 出网代理与端口：哪个用途走哪个端口、怎么启停
- `apis.md` — 外部 API 依赖（非模型）：提供商、端点、凭据去哪取、计费形态
- `services.md` — 本地与内网服务端点：搜索桥、MCP 桥、WebUI——端口、启停、健康检查
- `tools.md` — 本地工具与可复用脚本：稳定角色名、路径/命令、适用场景
- 需要时按同一模式扩展——一资产类，一表

不确定资产进哪张表：**你调用但不归你运行的端点 → `apis.md`；你自己跑起来的端点 → `services.md`；你在 shell 里执行的命令 → `tools.md`**。

## 2. 协议四条（必须）

1. **先查后问** — 遇到「用哪个模型 / 走哪个代理 / 调哪个 API / 服务怎么启 / 工具在哪」类问题，先查 `registry/` 对应表；查不到才允许问用户。

2. **变更即登记** — 任何配置变更（新增 / 更换 / 停用）完成后，agent 主动更新对应表，并刷新该行「更新日期」。
3. **单一权威源** — 注册表是唯一权威；其他文档与指令只引用表名，不复制内容——换配置只改表，全工作区生效。
4. **密钥不登记** — 表里只记凭据「去哪取」（如 `.env` 变量名、配置文件路径），绝不写密钥本身。

## 3. 表格约定

- Markdown 表格：LLM 与人都能直读直改，diff 友好。
- 每行一个资产；固定含「状态」与「更新日期」两列。
- 停用资产**不删行**：状态改「停用」并注明替代者，保留决策痕迹。

## 4. 反模式

- **把密钥写进表里**：注册表会进备份、进同步、进截图。
- **同一配置多处各写一份**：改一处漏三处——引用表，别复制表。
- **只登记不更新**：过期信息比没有信息更危险，所以「更新日期」列是强制的。
