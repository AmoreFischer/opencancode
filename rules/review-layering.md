# 分层审查协议（Layered Review）

> 审查 / 巡检 / 检查类任务的注入纪律：**O(命中区) 替代 O(全仓)**。依据：context rot 实证——任务难度不变、只增加输入长度，模型性能非均匀持续退化（18 个主流模型均如此）；一次性全量注入是双重亏损：成本线性涨，准确率还在跌。版本 v1.0。
>
> [溯源: Chroma《Context Rot》2025-07；Anthropic JIT 检索 / 渐进披露（上下文只放轻量标识符，运行时按需拉取）；Aider repo map（~1k token 高信号骨架抵整仓）]

## 三层模型

```
审查请求
  ↓ L0 索引层（定位，不读正文）
  ↓ L1 取证层（只读命中段落）
  ↓ L2 深读层（兜底，须声明理由）
  ↓ 报告（结论带行号证据）
```

### L0 索引层

目的：定位嫌疑区，产出「嫌疑清单 ≤10 项」（文件+行号/符号 + 一句怀疑理由），**不读正文**。

| 对象 | 工具 |
|---|---|
| 代码类 | repo-map / 代码图谱工具（符号、调用链、引用查询）；无此工具时 glob+grep 手工构造索引 |
| 非代码类 | 索引/登记表类文件（技能清单、资产注册表、学习库索引）、文件名扫描 |

### L1 取证层

grep / 带行号的定向读取——只读 L0 命中的文件目标段落。**报告的全部证据来自此层。**

### L2 深读层

整文件读。须显式声明「L1 证据不足 + 具体理由」后方可执行，禁止默认。

## 硬规则

1. **禁止跳过 L0 直接 L2**——「检查时一次性注入大量项目内容」即此违规形态；
2. **预算锚**：单次审查注入 ≤30k token（按模型窗口与任务规模可调，但必须有锚）；超出 = L0 失败信号，回退重做 L0（细化嫌疑清单），而非继续灌上下文；
3. **证据分级**：报告结论每条带 L1/L2 证据（行号引用）；「文件已改 / 模拟测试通过 / 真实调用成功 / 线上生效」是四级不同证据，分别报告不混称。

## 降级链

代码图谱工具不可用 → glob+grep 手工构造索引层 → 仍失败 → 停车报告（说明缺什么），**不静默跳层**。

## 豁免

全量盘点性质的任务（系统性大扫除、月度资产盘点等）显式豁免——其任务定义即全量遍历，分层无意义。

## 反模式

- **跳过 L0 直接整仓读**：双重亏损（贵 + 降智）——先索引定位再取证；
- **预算超标继续灌**：超过锚还往上下文里塞 = 回退信号被无视——重做 L0 而非继续注入；
- **L2 无理由默认**：整文件深读必须有「L1 不足 + 理由」的显式声明；
- **结论无行号证据**：「看起来没问题」不是审查产出——每条结论挂 L1/L2 取证。
