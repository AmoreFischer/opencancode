# 吸收对照表模板（Absorption Registry）

> 复制到工作区 `registry/absorption.md`。回答一个问题：**某外部仓库/来源被用了/吸收了，用在哪？**
> 规则见 [rules/registry.md](../rules/registry.md) §5。与扩展注册表分工：那张表管「装不装」的**决策生命周期**，本表管「用在哪」的**应用映射**；安装类条目两表各一行、经编号互引，本表不重复维护决策理由/回滚方式（DRY）。

```markdown
# Absorption Map — 仓库吸收对照表

> 仓库 → 吸收内容 → 应用节点 → 应用工作流 → 应用产物。

## 登记字段

| 字段 | 说明 |
|------|------|
| 仓库 | 外部来源（GitHub URL / 论文 / 文档 / 文章；非仓库来源注明类型） |
| 吸收内容 | 拿了它的什么（一句话） |
| 应用节点 | 哪个平台/运行时 |
| 应用工作流 | 哪个技能 / 规则 / 链路 / 场景 |
| 应用产物 | 落地文件路径 + `[溯源:]` 标注位置（若有） |
| 关联 | 扩展注册表编号（未登记者写 —） |

## 一、安装启用类（本地实装，决策细节见扩展注册表）

| 仓库 | 吸收内容 | 应用节点 | 应用工作流 | 应用产物 | 关联 |
|------|----------|----------|------------|----------|------|
| <repo-url> | <装了它的什么> | <平台> | <哪个场景/链路> | <落地文件路径> | ext-001 |

## 二、内化吸收类（不装本体，提取思路/规则/模式进体系）

| 仓库/来源 | 吸收内容 | 应用节点 | 应用工作流 | 应用产物 | 关联 |
|-----------|----------|----------|------------|----------|------|
| <repo-url> | <拿了思路/规则/模式> | <平台> | <哪个技能/规则> | <落地文件 + [溯源:]> | — |

## 三、拒绝 / 归档 / 暂缓类（防重复评估，决策理由见扩展注册表）

| 仓库 | 一句话去向 | 关联 |
|------|-----------|------|
| <repo-url> | <已拒绝（理由）/ 已归档 / 暂缓（重评触发器）> | ext-003 |

## 同步机制

1. **扩展登记联动**：新扩展在扩展注册表登记的同时，在本表登记一行（安装/拒绝/归档均登记——拒绝项也是溯源资产，防止未来重复评估）。
2. **思路吸收联动**：凡采纳外部方案并留 `[溯源:]` 标注的，同步登记本表内化节。
3. **月度对账**：抽查本表与全仓 `[溯源:]` 标注的一致性。
```
