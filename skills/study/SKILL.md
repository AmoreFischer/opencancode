# Skill: 好好学习 📚

> 版本：7.2 | 安全等级：🟡 中风险（有网络请求，注意速率与来源可信度）
> 技能 id 为 study，标题沿用中文习惯名「好好学习」。

---

## 目标

<HARD-GATE>
开始学习前**必须**检查 `learning/_doc_status.md` 和 `learning/_index.md`（若你维护这两个索引），确认该项目是否已学习过。重复学习是浪费。
</HARD-GATE>

当用户提供 GitHub 仓库、网站、技术关键词、或**需求探索问题**时，**评估是否值得学习 / 扫描生态找方案，按需产出分析或调研文档**，所有产出归档到 `learning/` 或 `plans/` 目录，并维护索引和溯源关系。

## 学习前自检（Karpathy 准则）

> 来源：Karpathy 编码准则（同本仓 [rules/iron-rules.md](../../rules/iron-rules.md) #12-#15）

1. **先想清楚再动手** — 明确目标：你要解决什么问题？不是"学了再说"
2. **简单优先** — README 能解决的不需要读全部源码
3. **精确修改** — 每条结论都要有来源
4. **目标驱动** — 读完能回答什么问题？能产出什么行动项？

## 四模式体系

| 模式 | 触发词 | 一句话 | 产出时间 |
|------|--------|--------|---------|
| **A 快速学习** | 「学习 <URL>」「看看」「评估一下」 | 单项目分析，产出 INDEX.md + 全览说明 | 15-30min |
| **B 深度研究** | 「深度研究」「专题分析」 | 多专题源码级分析，适合高价值项目 | 多天多阶段 |
| **C 需求调研** | 「怎么做」「如何」「有什么工具」+ 需求描述 | 生态扫描找方案，产出快照+方案 | 30-60min |
| **E 横纵分析** | 「横纵分析」「研究一下」「竞品分析」 | 纵向追时间深度+横向追竞品广度 | 30-60min |

> 各模式的详细流程、输出结构、评分标准 → 见对应 `<supporting-info>`

### 模式识别优先级

```
1. 显式指定（"深度研究 xxx"）→ 模式B
2. 显式指定（"横纵分析/竞品分析 xxx"）→ 模式E
3. 需求句式（"怎么做/如何/怎么" 开头）→ 模式C
4. 具体 URL 或项目名 → 模式A
5. 模糊关键词 → 模式A（先搜索再分析）
```

**注**：「沉淀技能 / 把这个写成技能」→ 直接进入结晶检测（`<supporting-info id="crystallization">`）。

## 价值评分（5 秒评估）

| 维度 | 权重 | 评分依据 |
|------|------|---------|
| **与当前项目的关联度** | 40% | 能否直接指导架构/代码/技能决策 |
| **新颖性** | 25% | 是否填补知识空白 |
| **可操作性** | 20% | 是否有具体 action items |
| **社区验证** | 15% | ⭐数、活跃度、issue 质量 |

**评分 >= 8.0 且高度相关** → 建议升级（A→B）
**评分 < 8.0** → 归档，保留 INDEX.md

## 学习入口识别

| 用户输入 | 模式 | 核心动作 |
|----------|------|---------|
| `github.com/<owner>/<repo>` | A | GitHub API + curl README |
| 任意 `https://` URL | A | curl / Jina Reader → 降级浏览器渲染抓取 |
| 纯文字/关键词 | A | GitHub Search API → 用户选择 |
| npm/PyPI 包名 | A | registry API 获取 metadata |
| **「怎么做/如何」+ 需求描述** | **C** | 需求解析 → 生态扫描 → 快照+方案 |
| 「深度研究」+ 项目名 | B | 多专题深度研究 |
| 「横纵分析/竞品分析」+ 对象名 | E | 双轴分析 → 结构化报告 |

## 学习前检查清单

1. **读 `learning/_doc_status.md`**：确认是否已学习过
2. **读 `learning/_index.md`**：查看相关项目评分和状态
3. **如果已学习**：
   - 🟢 活跃 → 告知已有报告，问是否更新
   - 🔴 归档 → 告知归档原因，问是否重新评估
   - 🔵 深度研究 → 直接引用深度研究报告
4. **如果未学习** → 正常执行

## 约束

### 必须做
- 文档语言与用户沟通语言一致，通俗易懂
- 每份报告必须包含「一句话结论」「与当前项目的关系」「行动建议」
- 模式A/B → `learning/repos/<名称>/` 或 `learning/websites/<名称>/`
- 模式C → `plans/YYYY-MM-DD_<需求名>/`
- INDEX.md 是模式A/B 必须产出（100 words 摘要 + 评分 + 推荐）
- 模式C 必须产出 snapshot.md + plan.md
- 执行完毕后更新 `learning/_index.md` 和 `learning/_doc_status.md`
- 然后 git commit + push
- 安全：仓库 > 500MB 拒绝 clone，磁盘 < 10GB 停止

### 不要做
- ❌ 不生成无意义的凑字数内容
- ❌ 不脱离当前项目上下文做纯学术分析
- ❌ 不轻易 clone 仓库（优先 API + curl README）
- ❌ 不忽略小仓库（低星仓库也可能有价值）
- ❌ 大任务分阶段，上下文过半时提醒用户压缩
- ❌ 不在未检查索引的情况下重复学习

## 模式C：需求调研（详细）

**输出结构**：
```
plans/YYYY-MM-DD_<需求名>/
├── snapshot.md     ← 调研快照（仓库列表+对比矩阵+安全评估）
└── plan.md         ← 落地方案（优先级+工作清单）
```

**核心流程**：
1. **需求解析** → 提取关键词（中英文各一组）+ 相关平台
2. **生态扫描** → 按你的扫描源清单顺序扫描（自建：常用搜索渠道 + 优先级排序，每个来源最多取 10 条）
3. **快速筛选** → 每个候选 README 分析 + 价值评分
4. **生成快照** → 对比矩阵 + 安全评估（依赖健康度/维护状态/许可证）
5. **生成方案** → 优先级 + 工作清单
6. **更新索引** → 更新 `learning/_index.md`

**与模式A/B/E 的衔接**：
- 模式C 发现高价值项目 → 建议用模式A 深入学习
- 模式A 评分 >= 8.0 → 建议升级模式B

</supporting-info>

## 模式E：横纵分析法（详细）

**方法论**：纵向追时间深度，横向追同期广度，最终交汇出判断。

**核心流程**：

1. **明确研究对象** — 确认名称、类型（产品/公司/概念/人物）、关注点
2. **信息收集** — 按以下优先级获取信息：
   - 纵向：起源、创始人、发展历程、关键事件、版本迭代、融资、战略转向
   - 横向：竞品识别、各竞品特点、行业对比、市场份额
   - 补充：用户社区讨论、行业环境变化
   - **搜索策略**：多次搜索、多关键词组合，一手来源优于二手来源
3. **纵向分析**（5000-12000 字）— 沿时间轴还原发展全貌：
   - 起源追溯、演进历程、决策逻辑、阶段划分
   - **写成叙事故事体**，不是年表流水账
4. **横向分析**（3000-8000 字）— 当前切面与竞品对比：
   - 判断竞品：无直接竞品 / 少量 / 充分
   - 核心差异、用户视角、生态位分析
5. **横纵交汇洞察**（1500-3000 字）— 两条线交叉产出新判断：
   - 历史如何塑造当下竞争位置
   - 未来推演：三个剧本（最可能/最危险/最乐观）
6. **产出报告** → `learning/research/<对象名>_横纵分析报告.md`

**总篇幅**：10000-23000 字

**写作风格**：
- 句子时长时短，有节奏感
- 敢下判断，推测明确标注
- 知识是「聊着聊着顺手掏出来」的，不是科普式灌输

**绝对禁区**：
- 套话：「首先...其次...最后」「综上所述」「值得注意的是」
- 空洞形容词：「赋能」「抓手」「打造闭环」
- 教科书开头：「在当今AI快速发展的时代」
- 高频踩雷词：「说白了」「意味着什么？」「本质上」「换句话说」
- 编造场景：搜不到的信息诚实标注「暂缺」

**质量自检**：
- [ ] 纵轴是叙事故事体？有因果逻辑和时代脉络？
- [ ] 关键节点都展开写了，没有蜻蜓点水？
- [ ] 横轴竞品分析够深？引用了真实用户声音？
- [ ] 交汇洞察产出了新判断，不是前面内容的缩写？
- [ ] 没有触犯绝对禁区？

**与模式 B 的区别**：
- B 是开放式多专题，适合技术项目源码级分析
- E 是双轴结构化，适合产品/公司/概念的全景分析

</supporting-info>

## 关键工具命令

```bash
# GitHub 仓库元信息
curl -s "https://api.github.com/repos/<owner>/<repo>" | jq '{name, description, stargazers_count, language, topics, license: .license.spdx_id}'

# GitHub README（base64 解码）
curl -s "https://api.github.com/repos/<owner>/<repo>/readme" | jq -r '.content' | base64 -d

# GitHub 搜索
curl -s "https://api.github.com/search/repositories?q=<关键词>&sort=stars&per_page=5" | jq '.items[] | {full_name, description, stargazers_count, html_url}'

# 网站内容抓取（首选，纯文本化）
curl -sL --max-time 30 "https://r.jina.ai/<URL>"

# 磁盘空间检查
df -h . | tail -1
```

### 网页抓取降级策略

当 curl / Jina Reader 返回空或不完整（SPA 动态页面），自动降级：

1. **浏览器渲染抓取** — 用你环境里的浏览器自动化（Playwright / 浏览器 MCP / headless 浏览器）拿渲染后 DOM
2. **仍失败** — 截图 + 人工判读，或换来源（镜像/文档站/缓存）

### 支持的来源

| 来源 | 方式 | 需要克隆 |
|------|------|---------|
| GitHub 仓库 | GitHub API | ❌ |
| 技术博客/文章 | curl/Jina Reader | ❌ |
| npm/PyPI 包 | registry API | ❌ |
| HuggingFace | HF API | ❌ |
| SPA/动态网站 | 浏览器渲染降级 | ❌ |
| 关键词搜索 | GitHub Search API | 视情况 |

## ⚠️ 踩坑记录

| # | 踩坑 | 解决方案 |
|---|------|---------|
| 1 | `.gitignore` 规则误忽略学习产出目录 | `git add -f` 强制添加或修 .gitignore |
| 2 | GitHub API 速率限制（60次/小时未认证） | 大量请求用 `gh api` 或加 token |
| 3 | curl README 返回 base64 需要解码 | `base64 -d` |
| 4 | Jina Reader 需要代理环境 | 先检测 `$http_proxy` |
| 5 | 大仓库克隆耗时占空间 | 优先 API 分析 README |
| 6 | 上下文不够分析大 README | 分段读取，优先前 500 行 |
| 7 | git commit 中文路径显示转义 | 正常现象 |
| 8 | 学习报告写太长没人看 | 控制在 200-400 行 |
| 9 | `since` 日期过滤 git log 时区不对 | 用 `git log --oneline -N` |
| 10 | 重复学习已有项目 | 先查 `_doc_status.md` |
| 11 | 模式C 生态扫描耗时过长 | 按扫描源优先级，每个来源最多 10 条 |
| 12 | 模式C 需求句式误识别 | "学习 X"=A，"学习 怎么用 X"=C |
| 13 | curl/Jina 返回空（SPA） | 降级浏览器渲染抓取 |

</supporting-info>

## 💎 学习结晶

> 灵感：Hermes Agent 学习闭环 — 学习 → 结晶 → 技能 → 自我改进

每轮学习完成后，**自动执行结晶检测**：

| 检测项 | 条件 | 结晶动作 |
|--------|------|---------|
| 🛠️ 新技能？ | 产出中有可复用工作流程（≥3步） | 建议注册为新技能（写入你的技能目录） |
| 📖 新指南？ | 产出中有环境配置/部署的完整步骤 | 建议创建指南文档 |
| 🧠 新记忆？ | 产出中有踩坑/限制/兼容性经验 | 建议写入踩坑记录（见本仓技能「小本本」） |
| 📐 新规范？ | 产出中有架构模式值得全局遵守 | 建议更新 agent 指令文件（AGENTS.md 等） |
| 🔄 融合？ | 新产出与已有技能重叠或互补 | 建议合并/升级现有文件 |

### 结晶执行规则

1. **只建议不自动执行** — 列出候选，用户确认
2. **深度研究必结晶** — 模式B 完成后结晶检测是强制的
3. **快速学习可选** — 模式A 简化为一句话总结

### 结晶输出格式

```
💎 学习结晶检测：

🛠️ 新技能候选：
  - 「xxx工作流」→ 建议注册为技能（原因：...）

📖 新指南候选：
  - 「xxx部署」→ 建议创建指南（原因：...）

🧠 新记忆候选：
  - 「xxx坑」→ 建议写入踩坑记录（原因：...）

（或）
✅ 无结晶项 — 本次学习为纯情报/评估，无需沉淀。
```

</supporting-info>

## 学术研究模式（论文 / 科研场景）

> 来源：nature-skills / paper-craft-skills / ljg-skill-xray-paper / ljg-skill-paper（GitHub 技能库学习吸收，见 SOURCES）
> 适用：论文阅读、科研绘图、学术写作
> 触发：学习对象含 `arxiv` / `nature` / `paper` / `论文` / `科研` 关键词时，在模式 A/B 上叠加此流程

论文 / 学术技能库的解构流程（叠加在模式 A/B 之上）：

| 步骤 | 动作 | 来源思路 |
|------|------|----------|
| 结构解构 | 拆为：一句话压缩 / 核心方法 / 餐巾纸公式 / 缺口与增量 | ljg-skill-xray-paper |
| 钥匙概念 | 1-3 个关键概念，费曼式从零讲透 | ljg-skill-paper |
| 认知碰撞 | 与已知方法的差异、对当前项目的可迁移点 | paper-craft-skills |
| 声明核验 | 每个关键声明回溯原文出处、标注来源链接、逐条 fact-check（不确定的诚实标注"待核实"） | Hermes Agent Grounded Citations |
| 科研绘图 | 关键图表用规范学术风格重绘 | nature-skills |

> 原则：不装上游技能库本体，只吸收"学术解构流程"作为模式 A/B 的论文专用叠加层。
