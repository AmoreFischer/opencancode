# Skill: 深挖 🕵️‍♂️

> 一个公司/行业/产品的表层之下，发生了什么？
> 扒皮式多维度深度研究，输出叙事而非数据。
> 安全等级：🟢 低（只读研究）；依赖联网搜索与网页抓取能力

---

## 目标

当用户说"看看茅台/宁德/特斯拉/芯片/光伏背后有什么故事"时，
不是查股价涨了跌了，而是从**六个维度**挖出深层叙事：

```
用户输入: "茅台"
  ↓
┌── 维度 1: 供应链与原料 ────── 粮食涨价？水源变化？产能瓶颈？
├── 维度 2: 公关与舆论 ──────── 最近出了什么事？舆情风向？
├── 维度 3: 政策与环境 ──────── 监管收紧？税收变局？产业政策？
├── 维度 4: 社会变迁 ────────── 消费习惯变了？年轻人怎么看待？
├── 维度 5: 行业竞争格局 ────── 谁在挑战？替代品威胁？
└── 维度 6: 时间线叙事 ──────── 这件事是怎么一步步走到今天的？
  ↓
输出: 一篇有逻辑的"故事"，不是数据表格
```

---

## 流程

### 阶段 1：明确目标

用户说了一个词，执行前先确认挖掘方向：

```
用户说: "看看茅台"
→ 自动覆盖: 供应链 / 舆论 / 政策 / 社会变迁 / 竞争
→ 如有特别关注点，先问一嘴: "是重点关注供应链、还是最近有什么新闻？"
```

如果用户没说具体维度，**全量覆盖 6 个维度**。

### 阶段 2：多维度搜索

对每个维度，执行搜索（示例以通用搜索引擎措辞，按你的免费搜索链路调用）：

| 维度 | 搜索方向 | 示例 query |
|------|---------|-----------|
| 供应链原料 | 原材料价格、产能、产地、技术瓶颈 | `贵州茅台 高粱 采购价 2026` |
| 公关舆论 | 近期事件、争议、负面、口碑 | `贵州茅台 争议 新闻 2026` |
| 政策环境 | 监管、税收、产业政策 | `白酒 消费税 政策 2026` |
| 社会变迁 | 消费趋势、代际变化、替代品 | `年轻人 白酒 消费趋势 2026` |
| 竞争格局 | 对手、份额、替代品 | `白酒 行业 竞争格局 2026` |
| 时间线 | 关键节点历史 | `贵州茅台 大事记 2020 2026` |

每个维度搜索 2-3 条不同来源，避免单一信源偏见。

### 阶段 3：纵深阅读

对搜索结果中最有价值的 3-5 篇文章读详情。
选文章标准：
- 有具体数据/日期/人物
- 来源可靠（新闻媒体/研究报告）
- 不是纯广告/营销稿

### 阶段 4：串联叙事

把 6 个维度的信息串成一条逻辑线，用"讲故事"的方式输出。

**叙事结构**：

```
📖 <标题>

1️⃣ 引子 — 一个具体的切入点（最近的新闻/数据/事件）
   把读者拉进来

2️⃣ 供应链深挖 — 原料从哪里来，价格发生了什么变化，为什么
   有具体数字："高粱采购价同比上涨XX%"

3️⃣ 公关/舆论风云 — 最近发生了什么事件，舆论怎么演变
   有时间线，有各方反应

4️⃣ 政策与外部环境 — 监管怎么变化，政策如何重塑行业
   客观叙述，不是站队

5️⃣ 社会变迁 — 更宏观的视角，消费习惯、人口结构、文化变迁
   这个维度最重要——讲出为什么这件事"不只是这家公司的事"

6️⃣ 时间线 — 这一切是怎么发展到今天的
   关键转折点、标志性事件

7️⃣ 尾声 — 现在站在什么位置，下一步可能是什么
   开放式的，不是预测是推演
```

**写作原则**：
- **有数据**：每个观点至少有一个事实/数字/引用支撑
- **有出处**：关键信息标注来源
- **有逻辑**：事件A → 原因B → 影响C，不断链
- **不装懂**：找不到的信息明确说"这方面公开资料有限"
- **不预测**：不装专家预测股价/价格，只推演可能性
- **不啰嗦**：每个维度 200-500 字，全文控制在 2000-4000 字

### 阶段 5：输出

输出到 `notes/{日期}_{主题}_深挖.md`（或你习惯的研究笔记目录）。

**产出标记**：新文件带 frontmatter：

```yaml
tags: [深挖, <行业/公司>, <维度标签>]
created: {YYYY-MM-DD}
source: "多源搜索 + 网页抓取交叉验证"
```

内容经用户确认后标记定稿，可选出 HTML 展示版。同时在对话中直接展示。

## 注意事项

- 不碰政治敏感话题
- 涉及竞争对手时保持中立描述，不踩一捧一
- 供应链信息可能滞后（公开数据更新慢），注明年份
- 这个技能的结果不是投资建议，开头加一句声明

## 检索哲学（无向量 RAG 启发）

> 来源：VectifyAI/PageIndex（见仓库 SOURCES.md）

深挖本质就是"非向量"研究——不靠关键词相似度盲选，靠结构与推理定位：

- **similarity ≠ relevance**：搜索结果排名靠前 ≠ 真正回答了"背后故事"。选文章看重相关性，而非关键词命中度。
- **结构优先**：先扫文章目录/小标题/结构，判断是否含目标维度的深度内容，再决定精读（对应阶段 3「选文章标准」）。
- **推理选段**：多维度搜索后，靠推理判断"哪篇真正讲清了供应链/舆论/政策"，而非哪篇关键词堆得最多。

## 验证

- [ ] 用户给了一个词 → 已确认焦点（全量/特定维度）
- [ ] 6 维度各搜索 2-3 次，多信源交叉
- [ ] 精读 3-5 篇最有价值的文章（按选文标准，非排名）
- [ ] 按叙事结构串联成文；每个观点有支撑、关键信息有出处
- [ ] 已落盘 + 对话展示 + 开头含非投资建议声明
- [ ] 邀请用户反馈（"还想深挖哪个方向？"）

**On failure:** 缺维度补维度；信源单一 → 换渠道重搜，不硬编。
