# 拆分模式库

> 每次完成上帝文件拆分后，在此追加模式卡片。
> 格式：模式名 → 信号 → 做法 → 实例 → 成功率

## P1: 职责边界拆分

- **信号**：文件内有多个不相关功能域（如：日志 + API 客户端 + 调度器）
- **做法**：按功能域拆成独立文件，原文件变薄层路由/入口
- **实例**：`core.py` 605→288 行（拆出 logger.py / api_client.py / scheduler.py）
- **成功率**：高

## P2: 组合提取（Manager 模式）

- **信号**：文件内有一个独立的状态管理域（如资源索引），有自己的 load/save/数据结构
- **做法**：提取为独立类，父类通过 `self.xxx = XxxManager(dir)` 组合，父类保留委托方法
- **实例**：`draw_handler.py` 515→372+181 行
- **关键**：被提取的类应自包含（自己的持久化、自己的索引），不依赖父类的状态
- **成功率**：高

## P3: 路由层分离

- **信号**：模块级函数（init/handle/handle_*）与类定义混在同一文件
- **做法**：类抽到独立文件，原文件只留路由分发 + 常量 + 注入函数
- **实例**：`draw.py` 937→88+639+135 行
- **关键**：入口文件的导入路径不变（从原文件导入 init_handler/handle 等），实现零侵入
- **成功率**：高

## P4: 封装修复（私有属性 → 公共方法）

- **信号**：外部模块直接访问 `obj._private_attr`（下划线属性）
- **做法**：新增公共方法封装访问逻辑，外部调用方法而非直接读属性
- **实例**：`router.py` 直接访问 `handler._submitted_lock` → 改为 `has_submitted(id)` 公共方法
- **关键**：公共方法比暴露私有属性更安全，因为方法可以包含过期判断等业务逻辑
- **成功率**：高
