# Skill: 知识库进化 🧬

> 版本：1.1 | 安全等级：🟡 中风险（修改服务配置/代码文件 + 重启服务，需确认）
> 前提：知识服务有问答日志（含用户反馈字段与分类结果）。无日志则先加埋点，再谈进化。

---

## 目标

对运行中的知识库/问答服务（RAG Bot、FAQ 服务、领域知识库），从**用户反馈与运行日志**诊断问题，优化分类与知识内容，形成自进化闭环：

```
qa_logs（问答日志）
  → 负面反馈 👎 / 兜底分类 general 案例
  → 四类诊断 + 归因分析
  → 关键词 / prompt / 知识内容优化
  → evolution_tasks（进化任务台账）
  → 重启生效 → 下一轮反馈
```

---

## 工作流

### Step 1: 数据采集

从问答日志取近 7 天的负面反馈与兜底分类案例（示例 SQL，按你的表结构改写）：

```sql
-- 近 7 天负面反馈 + 兜底分类案例
SELECT id, timestamp, question, domain, feedback, reply
FROM qa_logs
WHERE timestamp >= datetime('now', '-7 days')
  AND (feedback = 'negative' OR domain = 'general')
ORDER BY timestamp DESC
LIMIT 20;

-- 进化任务统计
SELECT status, COUNT(*) FROM evolution_tasks GROUP BY status;
```

### Step 2: 诊断分析

对每个案例判断问题类型：

| 问题类型 | 检测条件 | 优化动作 |
|----------|----------|----------|
| `keyword_miss` | `domain=general` 但问题含具体领域词 | 在领域关键词配置中补关键词 |
| `wrong_domain` | 负面反馈 且问题应属另一个领域 | 调整关键词优先级 |
| `bad_reply` | 负面反馈 但分类正确 | 检查知识摘要质量，改进内容 |
| `missing_knowledge` | 回复含"暂无相关资料" | 标记需要补充知识文件 |

### Step 2.5: 归因分析（多领域回答收到负面反馈时）

先查分类细节（每个关键词命中了哪个领域），再按矩阵归因：

| 场景 | 归因判断 | 优化动作 |
|------|----------|----------|
| 单领域 + 👎 | 该领域知识不足或回复质量差 | 检查知识摘要 / 优化 prompt |
| 多领域 + 👎 + 某段很短（<20字） | 短段落对应的领域知识缺失 | 标记 `missing_knowledge` |
| 多领域 + 👎 + 分类细节有误分类 | 关键词归属错误 | 调整关键词配置 |
| 多领域 + 👎 + 分类正确但答案不对 | LLM 理解问题 | 优化 system prompt 规则 |

分类细节字段示例（key=命中的关键词，value=匹配到的领域）：

```json
{"发财树": "plant_care", "怎么养": "plant_care", "多少钱": "product_price"}
```

### Step 3: 执行优化

**关键词优化**（最常见）：
1. 读取领域关键词配置文件
2. 分析案例中的问题文本，提取应命中的关键词
3. 将新关键词添加到对应领域列表（遵循现有格式）

**system prompt 优化**：
1. 读取服务的 system prompt 模板
2. 根据负面反馈模式调整规则
3. 写回并记录变更点

**知识内容补充**：对 `missing_knowledge` 案例，标记待补知识文件，交由内容维护流程。

### Step 4: 记录 + 生效

1. 将优化动作记入进化任务台账（表或 md 均可，字段：type / detail / related_log_ids / status）：

```sql
INSERT INTO evolution_tasks (type, detail, related_log_ids, status)
VALUES ('keyword_miss', '添加XX等领域词到 domain_a', '1,2', 'applied');
```

2. 重启服务使配置生效，并验证启动状态正常
3. 下一轮反馈数据进来后，检查对应案例是否不再复现（闭环验证）

## 约束

### 必须做
- 先读数据再分析，不要凭空猜测
- 每次优化后记录到进化任务台账
- 修改配置后必须重启服务并确认状态正常
- 关键词添加遵循现有格式与语言习惯

### 不要做
- ❌ 不要删除现有关键词，只能新增（create-only）
- ❌ 不要修改问答日志历史数据
- ❌ 不要一次添加超过 10 个关键词（防止过拟合）
- ❌ 不要在没有负面案例的情况下"预防性优化"
