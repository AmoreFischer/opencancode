# Skill: 扩展管理 📦

> 版本：1.1 | 安全等级：🟡 中（涉及安装外部依赖，有供应链/稳定性风险）
> 依赖：扩展注册账本（建议 `registry/extensions-registry.md`，唯一事实源）

---

## 目标

把"装外部扩展"这件事纳入 **可注册、可追溯、可启停、可回滚** 的管控。

装可以，但：不能偷偷装、不能装完就忘、不能不知道为了什么装、不能 agent 已有等价能力还重复装。

> 这是「原创吸收、减少依赖」原则的那道栅栏：依赖可以装，但**可溯源**不能打折。

<HARD-GATE>
执行 `npm i` / `uvx` / `npx ... add` / `pip install` / MCP 配置写入 / 二进制下载 / 桌面应用安装 **之前**，必须先在扩展注册账本登记一条（决策状态 = 待评估）并完成评估。**未登记不得安装。**
</HARD-GATE>

---

## 什么时候用 / 不用

| ✅ 用 | ❌ 不用 |
|-------|---------|
| 要装任何第三方插件/MCP/CLI/依赖/skill-pack | 只用 agent 内置工具（搜索/读写/grep 等） |
| 配置新的 MCP server | 用已有技能能覆盖的场景 |
| 教程/同事说"装个 X 就行" | 升级已登记扩展（走审查节奏即可，无需重新登记） |

---

## 反模式

- ❌ 偷偷 `npm i` 不登记 → ✅ 先登记 `ext-NNN`，评估准予后再装
- ❌ 装完不记配置落点 → ✅ 记录配置写到哪个文件，方便回滚
- ❌ 不留回滚方式 → ✅ 登记 uninstall 命令 / 禁用操作
- ❌ 重复评估已拒绝的扩展 → ✅ 查注册账本，"已拒绝/已原创替代"永久存档，不重装
- ❌ 已有等价能力还装 → ✅ 先查已有技能与内置工具，能替代就标"已原创替代"，不装

## 步骤

### 阶段 1：登记（安装之前）

1. 在注册账本分配 `ext-NNN`（递增，不复用）
2. 填字段：名称 / 类别 / 来源 / 吸收自 / 用途 / 决策状态 = 待评估
3. **查替代**（关键）：先看已有技能 + agent 内置工具，是否有等价能力
   - 有 → 决策状态改 `已原创替代`，填替代实现路径 → **流程到此结束，不装**
4. 查历史：账本是否曾拒绝/替代过同类扩展

### 阶段 2：评估

对每个"待评估"项回答四个问题：

| 问题 | 倾向结论 |
|------|----------|
| 已有 / 能低成本原创吗？ | 能 → `已原创替代` |
| 用途频次高吗（对照你的高频场景）？ | 低 → `已拒绝` 或暂缓 |
| 自研成本远高于安装成本吗？ | 是 → `准予安装` |
| 维护 / 安全 / 供应链成本可接受吗？ | 否 → `已拒绝` |

把结论写入"决策理由"字段。

### 阶段 3：安装（仅"准予安装"项）

1. 执行安装命令，记录到"安装方式"字段
2. 记录"配置落点"（配置实际写到的文件）
3. 记录"回滚方式"（uninstall / 禁用命令）
4. 生命周期状态：`待装` → `已装未启用`

### 阶段 4：启用

1. 确认启用范围（机器 / 平台 / 项目）
2. 启用并验证可用
3. 生命周期：`已装未启用` → `已启用`
4. **在"已启用扩展清单"加一行**（与登记表保持一致）
5. 登记启用日期

### 阶段 5：审查（持续）

- 收工时（[整理](../整理/SKILL.md) L2）：扫表标记可禁用/可替代项
- 每月：配合 [内肃](../内肃/SKILL.md) N3.5 全表审查
- 长期未启用 → `已禁用` → `已卸载`

## 产出

- **主产出：** 注册账本更新（新增/变更一行 + 已启用清单同步）
- **副产出：** 评估结论（写入决策理由字段）

---

## 验证

- [ ] 账本新增条目字段完整（尤其 来源 / 决策理由 / 回滚方式）
- [ ] 已查替代（已有技能 + 内置工具），无重复造轮子
- [ ] 若已启用：登记表生命周期状态 与 已启用清单 两处一致
- [ ] 配置落点已记录，回滚方式可执行
- [ ] 涉及凭据的扩展已走 `.env` + `.gitignore`（[凭据红线](../../rules/iron-rules.md) #21）

**失败处理：** 若发现已有等价能力 → 回退到阶段 1，改判"已原创替代"，不安装。

---

## 注意

- "已拒绝 / 已原创替代"条目**不要删**——它们是溯源资产，防止未来重复评估
- 安装类扩展在 [absorption 对照表]（若维护）同步登记一行：账本管"装不装"的决策，对照表管"用在哪"的映射
- 装完后建议触发一次 [整理](../整理/SKILL.md) L3，确认未引入预料之外的依赖蔓延
