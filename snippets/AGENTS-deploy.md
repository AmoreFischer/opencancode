# 部署门禁片段（OpenCanCode）

> **用法**：整段粘贴进任意 agent 的指令文件（`AGENTS.md` / `CLAUDE.md` / system prompt）。适用于在新环境/新设备上**安装、迁移、升级 agent 运行时及其配套**（CLI、桌面应用、插件生态、模型接入）的场景。配套实战案例见 [`examples/case-dsh-desktop.md`](../examples/case-dsh-desktop.md)。

## 部署前：环境检测（必须；检测 ≠ 授权）

用户要求部署/安装/迁移任何运行时之前，先完成以下检测并**汇报结果，然后停下等用户指令**——用户明确指定平台并确认后才开始动手：

1. **基础层**：OS / shell / 包管理器（node/npm、python venv、docker、git）的存在性与版本；
   - **PowerShell 版本形态**（Windows）：须为 7.x **MSI 版**（GitHub releases 直拉）；MSIX 版（winget msstore 源 / Store）有 AppContainer 沙箱限制，不利于 agent 驱动——检测到即报告并建议换装；
2. **数据层**：目标运行时的数据目录现状——已存在配置 = 有迁移面（先想备份与并存），全新 = 干净安装；
3. **模型层**（重点，缺任何一项都不算检测完成）：
   - API key 存在性：只验存在与非空，**禁止回显值**；
   - 端点连通：有代理先探代理，探不通就明说并等指示，**禁止静默直连**；
   - 运行时实际模型配置：当前默认模型、模型目录齐全度；
   - thinking/reasoning 类模型的调用约束：max_tokens 下限、不关闭 thinking、超时下限；
   - 一次**最小真实调用**验证——「配置存在」≠「真实调用成功」，只有后者算数；
4. **冲突层**：端口占用、同类既有安装、PATH 里的旧入口（并存还是替换，请用户裁决）。

## 部署中：证据链纪律

- 动数据/配置前先备份，**快照放在被改目录之外**（升级后的新进程不该能碰到它）；
- 关键配置文件记 SHA256 基线，每个阶段后对照——**认语义不认字节**：GUI 读-改-写回导致的 hash 变化属正常，配置格式/条目丢失才是回滚信号；
- 安装包先验哈希（对照官方更新清单的 sha512/sha256）再安装；
- 分阶段执行，每阶段有验证门禁，任一阶段失败即停并汇报，不带病推进。

## 部署后：汇报与登记

- 按「已完成 / 阻塞中 / 未开始」三态汇报，不虚称完成、不为凑数造下一步；
- 新资产（模型、端口、服务、工具、扩展）登记进工作区 registry 表；
- 回滚通道留档：旧入口**归档不删除**，观察期过后再清理。

## 反模式

- **检测完不等指令就开装**——检测不是授权，方案要用户拍板；
- **「配置文件在」就宣称「能用了」**——证据分级：文件存在 < 配置正确 < 真实调用成功；
- **备份放进被改目录里**——升级/迁移后可能被新进程读写甚至污染；
- **删掉旧入口图干净**——回滚通道随之消失，观察期前不清理；
- **静默降级**——代理不通就直连、免费通道失效就切付费，都不允许，先停车报告。
