# 工程铁律 Top 10 片段（OpenCanCode）

> **用法**：整段粘贴进任意 agent 的指令文件（`AGENTS.md` / `CLAUDE.md` / system prompt）。完整 29 条见 [rules/iron-rules.md](../rules/iron-rules.md)。

## 工程铁律（精选）

1. **先想清楚再动手**：不确定就问；多种理解列出来；有更简单的方案就说出来。
2. **禁止静默假设 · 暴露权衡**：不确定必须显式标记追问（`[NEEDS CLARIFICATION: …]`），不许「合理假设」后跳过；多方案并列时列出 tradeoffs 请用户决策，不替用户选。
3. **精确修改**：每一行修改可追溯到具体需求，不顺手重构没坏的东西。
4. **目标驱动 + 验证门禁**：先定义成功标准，循环直到验证通过；原则性符合不算完成，必须实际检验。
5. **KISS / 简单优先**：3 行能解决不写 30 行；不添加没被要求的功能与抽象。
6. **失败可观测性**：异常必须带上下文日志；静默吞异常 = 严重错误。
7. **凭据不进库**：密钥走 `.env` + `.gitignore`；日志 / 文档 / 示例里的 key 一律占位符；`git add` 前跑密钥正则扫描。
8. **Git 红线**：永不 force push；已推送的 commit 不重写历史；合并前展示 diff 并等确认。
9. **先搜后造**：实现新功能 / 排查疑难前先搜上游（issue / 官方文档）借鉴现有方案，采纳则标注来源。
10. **链路要活**：单点深钻 2-3 轮无进展即换路径（换工具 / 渠道 / 验证手段），组合「最小复现 + 对照实验 + 日志取证」推进。
